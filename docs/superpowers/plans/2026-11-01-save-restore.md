# Save and Restore Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every screamer object (functor, stream operator, backtest engine, Pipeline, live session) can be saved to a human-readable JSON file (or its CBOR twin) and loaded back in C++, Python or JavaScript, continuing bit for bit where it stopped.

**Architecture:** A new C++ module `include/screamer/serial/` holds one tree model (the existing `json::Value`), three archives (writer, validator, reader) and the JSON and CBOR encodings. Each operator describes its settings and its state once, in two template members that every archive runs, Boost.Serialization style; `EvalOp` and `dag::Resettable` gain virtuals that forward to them. Python and JavaScript are thin wrappers over the C++ calls, so all three write identical bytes.

**Tech Stack:** C++17, nanobind, Embind/WASM (js/), pytest, node test runner, Sphinx.

**Spec:** docs/superpowers/specs/2026-11-01-save-restore-design.md (approved 2026-11-01). Read it before any task.

## Decisions this plan adds to the spec

These are the plan's calls; every task follows them.

1. **Tree and text.** The tree is `screamer::dag::json::Value` (graph_json.h). Task 1 moves the `json` namespace into `include/screamer/common/json.h` (graph_json.h includes it, `dag::json` stays as an alias) and adds `json::dump_save(v)`. That function writes objects indented by 2 spaces, arrays whose elements are all scalars on one line, keys in insertion order, and numbers through the existing `float_text` (NaN, Infinity, -Infinity, -0.0 spelled out). `Pipeline.to_json` keeps using `json::dump` and does not change.
2. **Archives.** Each operator has
   - `template <class Ar> void settings(Ar& ar)`, which lists every constructor parameter in help.json order under its help.json name;
   - `template <class Ar> void state(Ar& ar)`, which lists every member that `reset()` touches.

   Three archive types run these members:
   - `serial::Writer` builds a tree.
   - `serial::Validator` checks a tree against the object's current settings and changes nothing.
   - `serial::Reader` assigns the values.

   A load always runs the Validator pass first and the Reader pass second. A failed load therefore leaves the object unchanged, including non-copyable composites. Field calls: `ar("name", scalar)`, `ar("name", std::vector<double>&)`, `ar.fixed("name", vec, expected_len)` (the length must equal `expected_len`), `ar.object("name", block)` (recurses into a building block's own `state`), `ar.op("name", EvalOp&)` (recurses into a nested operator through its virtuals), and `ar.check(cond, "message")` (an invariant such as `count <= capacity`).
3. **Versions.** Each operator declares `static constexpr int kStateVersion = 1;`. The file stores it per object as `"state": {"version": N, ...}`. A mismatch raises `serial::StateVersionError`, whose message names the object path and both versions.
4. **EvalOp virtuals** (on `EvalOp`, implemented once by a CRTP mixin `serial::Saveable<Derived>` that `ScreamerBase`, `FunctorBase`, `VarArityOp` and `RowOp` use):
   - `const char* type_name() const`
   - `void write_settings(json::Value&) const`
   - `void write_state(json::Value&) const`
   - `void read_state(const json::Value&, const std::string& path)`
   - `int state_version() const`
   - `bool saveable() const`

   An operator without `settings` and `state` yet reports `saveable() == false`, and saving it raises `serial::NotSaveable` with its name. A stateless operator declares an empty `state`.
5. **Settings live in C++.**
   - Each operator stores its constructor arguments as given. `EwMean`, for example, keeps which of com, span, halflife or alpha was passed. `settings` writes every help.json parameter with defaults filled in; an optional parameter that was not given is written as `null`.
   - A C++ factory registry `serial::make_op(type, settings) -> std::unique_ptr<EvalOp>` is generated by `devtools/gen_op_registry.py` from help.json and wasm_manifest.json into `src/screamer/serial/op_registry.cpp` (C++ users and the JS loader use it).
   - Python builds through its own wrapper classes, `getattr(screamer, type)(**settings)`, so `_screamer_params` and repr keep working.
   - `include/screamer/serial/settings_compat.h` holds the table of renamed parameters (type, old, new), initially empty, and the loader applies it before validating.
   - An unknown parameter raises an error that names it.
6. **File envelope.**
   - The file is `{"screamer": "save/1", "library_version": "<PROJECT_VERSION>", "object": <node>}`, where a node is `{"type": T, "settings": {...}, "state": {"version": N, "values": {...}}}` (a single series) or `{..., "state": {"version": N, "columns": [{...}, ...]}}` (a panel).
   - A settings-only file has `"state": null`.
   - A Pipeline node's settings are its `Pipeline.to_json` description unchanged. Its state is `{"version": 1, "engine": {...}, "nodes": {"<id>": {"version": N, "values": {...}}}}`, keyed by the graph walk's node id.
   - `PROJECT_VERSION` comes from CMake's `project(VERSION)` as a compile definition (never edit version files).
7. **Calls.** Python first, then JavaScript in its own casing:
   - `obj.save(path)` and `screamer.load(path, on_mismatch="error")`. The encoding follows the extension: `.json`, or `.cbor` for CBOR.
   - `obj.dumps(format="json")`, which returns `str` for JSON and `bytes` for CBOR, and `screamer.loads(data, on_mismatch="error")`.
   - `obj.settings()`, `obj.state()` and `obj.set_state(d)` work on JSON-native dicts.
   - `screamer.from_settings(d)` builds a fresh object with no state.
   - `on_mismatch="fresh"` keeps the file's settings and starts any object whose state does not fit fresh, with a `UserWarning` (JS: `console.warn`) naming it.
   - JS has `dumps`/`loads`/`settings`/`state`/`setState`/`fromSettings`, plus `save(path)`/`load(path)` that import `node:fs` lazily inside the function (no top-level Node globals, see the WASM browser rule).
   - A live session has `session.save(path)`, and `screamer.load` gives back a live session.
   - `Pipeline.save` saves settings only, and loading it gives a Pipeline.
8. **Resume.** Default batch calls keep decision D8 of `common/dispatch.h` (`EagerRun`): they start from a reset object and leave it reset, so value-by-value calls after a batch call start fresh, as today. `obj.resume(data)` (JS `resume`) is the one batch call that starts from the object's current (or loaded) state and leaves the end state in the object, so `f.resume(history)` on a fresh object is the warm-up call, after which `f` can be saved or fed value by value. It runs the generic per-step loop (`run_column` without `process_columns` / `process_array_*` fast paths), so no fast path has to support a non-fresh start.
9. **Panels.** Only `resume` on a 2D array (T, K) creates per-column state: on the first such call the object creates `panel_` with K clones of its freshly reset self (`virtual std::unique_ptr<EvalOp> clone_fresh() const`), runs column c on `panel_[c]`, and keeps them. Default 2D batch calls are unchanged and never create a panel. `panel_` is a `std::unique_ptr<serial::Panel>` member of `EvalOp`. A default batch call or `reset()` drops the panel (the object is reset anyway). A value-by-value call on an object holding a panel raises `ValueError("the object holds per-column state for 5 columns; call resume with a (T, 5) array, or reset() first")`. A 2D `resume` with another K raises `ValueError("resume: object holds 5 columns, got 3")`; a 1D `resume` on a panel object raises the same way. `RowOp`s (cross-section, portfolio engines) are already one object for K assets and do not use panels.
10. **Not saveable.**
    - A lazy (iterator) call in progress cannot be saved.
    - A poisoned live session raises on save.
    - A Pipeline holding a Python or JS callable raises on save, naming the node.
11. **CBOR** is an in-house codec `include/screamer/serial/cbor.h` (RFC 8949):
    - maps keep insertion order;
    - doubles are major type 7 float64, always 8 bytes, raw bits;
    - integers use major types 0/1;
    - no tags, no indefinite lengths.

## Global Constraints

- All logic in C++; Python and JS are thin bindings; Python-JS parity is a hard rule (every call in decision 7 exists in both).
- No per-sample cost. The hot loops are unchanged, so benchmark medians (`make benchmark` subset in Task 10) are within noise of main. Panels add memory, not work.
- Compatibility: no existing result changes; `Pipeline.to_json` output is byte-identical to main; existing saved Pipeline files load.
- Causal; batch == streaming; continuation is bit-identical (NaN compares equal to NaN).
- After C++ changes: `make install-dev POETRY_RUN= PY=/Users/thijs/screamer/.venv/bin/python PIP="/Users/thijs/screamer/.venv/bin/python -m pip"`. WASM: `cd js && npm run build:wasm && npm test`. Read and write text files with `encoding="utf-8"`. Never edit version files.
- Docs follow the style guide (feedback_writing_style), no em-dashes, US spelling.
- Commits with explicit paths; never `git add -A` or `git stash`.

## Review Focus

1. A hand-edited setting that the state depends on (`window_size` 20 to 50 with 20 buffered values) must refuse with a message naming the field, and with `on_mismatch="fresh"` must start fresh and warn. (Task 2 test `test_edited_setting_refuses_or_fresh`.)
2. NaN, Infinity and -0.0 in state and in settings (an infinite position cap) must round-trip in JSON and CBOR. (Task 1 `test_nonfinite_roundtrip`, Task 7 backtest cases.)
3. Save directly after construction, mid warm-up (count < window) and after a full window must all continue bit-identically. (The Task 2 registry test uses split points 0, 3 and 2*window.)
4. Corrupted files (unknown type, unknown field, missing field, wrong type, wrong length, truncated CBOR) must raise a named error, never crash, and leave the object unchanged. (Task 2 `test_bad_files_named_errors`, Task 10 fuzz.)
5. Switching between panel and single-series use (2D call, then a 1D call, then save) must save the mode actually in use. Resume with another column count must raise. (Task 3 `test_panel_mode_switch`.)
