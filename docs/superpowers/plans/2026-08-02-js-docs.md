# screamer.js Documentation Site - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An independent, JS-native documentation site for `@screamer-labs/screamer`: a TypeDoc API reference (every operator + the Pipeline API) with per-op descriptions seeded from `help.json`, a hand-written JS guide, published to GitHub Pages - separate from the Python ReadTheDocs, sharing only the op descriptions.

**Architecture:** The codegen (`gen_ts_api.py`) emits a JSDoc `/** short */` on each generated factory, sourced from the committed `help.json` (all 226 ops have an entry), so the JS API reference and the Python docs share one description source with no drift. TypeDoc builds an HTML API reference from the typed source plus hand-written Markdown guide pages. A GitHub Actions workflow builds and deploys the site to GitHub Pages.

**Tech Stack:** TypeScript, TypeDoc, Markdown, GitHub Pages (Actions deploy).

## Global Constraints

- Additive and docs-only. MUST NOT change any operator behavior, the C++/Python code, or the WASM/JS runtime logic. `gen_ts_api.py` gains JSDoc emission but the generated *code* (signatures, bodies) stays byte-identical apart from added comments; the JS test suite (66) stays green.
- Descriptions come from the committed `help.json` (deterministic, like `ctor_args`), so the freshness gate still reproduces byte-identically in any environment.
- The JS docs are independent from the Python docs in structure and voice. Follow the repo writing style (no em-dashes, lead with the point, plain language).
- No version file edits.

## File Structure

- Modify: `devtools/wasm/gen_ts_api.py` - emit a JSDoc block per factory from `help.json`.
- Modify: `js/src/generated/ops.ts`, `ops.d.ts` (regenerated with JSDoc).
- Create: `js/typedoc.json` - TypeDoc config (entry points, the guide documents, output).
- Create: `js/docs-guide/*.md` - the hand-written guide pages.
- Modify: `js/package.json` - `typedoc` devDep + a `docs` script.
- Create: `.github/workflows/js-docs.yml` - build TypeDoc + deploy to GitHub Pages.
- Modify: `README.md` - point the JavaScript docs link at the Pages URL.

### Task 1: Seed JSDoc from help.json in the codegen

**Files:**
- Modify: `devtools/wasm/gen_ts_api.py`
- Modify: `js/src/generated/ops.ts`, `js/src/generated/ops.d.ts` (regenerated)

**Interfaces:**
- Produces: each generated factory preceded by `/** <help.json short>. @param ... */` (a JSDoc block). The factory code (signature + body) is otherwise unchanged.

- [ ] **Step 1: Load help.json in the generator**

In `gen_ts_api.py`, load `screamer/data/help.json` (a committed file; the generator stays deterministic and needs no runtime `screamer` import - it already reads the manifest). Build `name -> short` (and `name -> parameters` if present, for `@param`). Handle both the dict and list JSON shapes.

- [ ] **Step 2: Emit a JSDoc block per factory**

Before each `export function <Name>(...)`, emit:
```ts
/**
 * <short from help.json, one line>.
 *
 * @param <argName> <the parameter's help.json description if available>
 * @see https://screamer.readthedocs.io/en/latest/ for the Python reference and full details.
 */
```
Escape any `*/` in descriptions. If an op has no `short`, emit a minimal `/** <Name> operator. */`. Keep the emitted factory signature/body identical to today - only prepend the comment. Emit the same JSDoc into `ops.d.ts` (so the API reference and editor tooltips both carry it).

- [ ] **Step 3: Regenerate + verify determinism**

Run: `python3 devtools/wasm/gen_ts_api.py && python3 devtools/wasm/gen_ts_api.py --check` -> `TS API OK: 226 factories`. Run it a second time with plain `python3` and confirm byte-identical output (deterministic). Grep `ops.ts` for a known description (e.g. `RollingMean`'s `Trailing-window arithmetic mean`).

- [ ] **Step 4: Freshness gate + suites**

Run: `poetry run pytest tests/test_ts_api_fresh.py tests/test_wasm_codegen_fresh.py -q` -> pass (the committed ops.ts now includes JSDoc; regeneration matches). Run: `cd js && npm run build:wasm && node --import tsx --test test/*.test.ts` -> 66/66 (JSDoc is comments; no behavior change), and `npx tsc -p tsconfig.json --noEmit` -> green.

- [ ] **Step 5: Commit**

### Task 2: TypeDoc API reference + the guide

**Files:**
- Create: `js/typedoc.json`
- Create: `js/docs-guide/index.md`, `getting-started.md`, `regimes.md`, `lifecycle.md`, `pipeline.md`, `parity.md`
- Modify: `js/package.json` (`typedoc` devDep + `docs` script)

**Interfaces:**
- Produces: `js/docs-site/` (the built HTML), from `npm run docs`.

- [ ] **Step 1: Install TypeDoc + config**

Add `typedoc` to `js` devDependencies (`npm i -D typedoc`). Create `js/typedoc.json`:
```json
{
  "entryPoints": ["src/index.ts"],
  "out": "docs-site",
  "name": "screamer.js",
  "readme": "docs-guide/index.md",
  "projectDocuments": ["docs-guide/getting-started.md", "docs-guide/regimes.md", "docs-guide/lifecycle.md", "docs-guide/pipeline.md", "docs-guide/parity.md"],
  "excludeInternal": true,
  "categorizeByGroup": true,
  "navigationLinks": { "Python docs": "https://screamer.readthedocs.io/", "GitHub": "https://github.com/screamer-labs/screamer" }
}
```
(Adjust keys to the installed TypeDoc version's schema; `projectDocuments` is the guide-pages mechanism in recent TypeDoc - if the installed version differs, use its documented equivalent and note it.)

- [ ] **Step 2: Write the guide pages** (repo writing style, JS-idiomatic, no em-dashes)

- `index.md`: what screamer.js is (the JS build of the screamer C++ engine; parity with Python), install, a 30-second example.
- `getting-started.md`: `npm i`, `await ready()` (why async), first op, first Pipeline.
- `regimes.md`: the four call regimes on one op (number, Float64Array/number[], iterable -> generator, async iterable -> async generator), container-preservation, `NdArray` for multi-output batch.
- `lifecycle.md`: `using`/`Symbol.dispose`, `.dispose()`, the FinalizationRegistry net, and that ops used in a Pipeline are pinned for the graph's lifetime.
- `pipeline.md`: `Input`, composing ops into a graph, `new Pipeline([in],[out])`, `p(feeds)`, `p.live()`, `combineLatest`/`resample`/`select`/`dropna`/`filter`/`delay`.
- `parity.md`: the JS build binds the same C++ core, so results match Python to 1e-9; link the Python reference for the deep per-op math.

- [ ] **Step 3: Build the site**

`js/package.json` script `"docs": "npm run build:wasm && typedoc"` (the wasm build ensures the generated module + types resolve for TypeDoc). Run: `cd js && npm run docs` -> `docs-site/index.html` exists with the API reference (all factories + `Pipeline`/`Input`/`ready`) and the guide pages in the navigation. Gitignore `js/docs-site/` (built output).

- [ ] **Step 4: Spot-check the output**

Confirm `docs-site` contains a page for `RollingMean` showing its help.json description, and the guide pages are present. Grep the built HTML for `Trailing-window arithmetic mean`.

## Notes for the executor

- JSDoc descriptions come from the committed `help.json`, so the generator stays deterministic (the same reason the `ctor_args` fix used it) and the freshness gate reproduces in CI. Do not introduce a runtime `screamer` import.
- The JS docs are independent: the guide is JS-idiomatic prose, not a port of the Python docs. Only the per-op `short` lines are shared, via `help.json`.
- TypeDoc's guide-page mechanism (`projectDocuments`/`--projectDocuments`) varies by version; use the installed version's documented approach and note any deviation.
- Enabling GitHub Pages (source = GitHub Actions) is a one-time repo-settings step for the user; the workflow is otherwise self-contained.
- Everything is additive under `js/`, `devtools/wasm/gen_ts_api.py`, `.github/workflows/`, and `README.md`. No behavior change; suites stay green.
